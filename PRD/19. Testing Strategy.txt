# 20. Testing Strategy

---

# 20.1 Introduction

Software testing ensures that VeriCart AI meets its functional and non-functional requirements while providing a secure, reliable, and user-friendly experience.

The testing strategy follows a layered testing approach, validating each component independently before verifying the complete integrated system.

Testing objectives include:

- Verify system correctness
- Detect defects early
- Validate AI outputs
- Ensure security
- Measure performance
- Improve software quality

---

# 20.2 Testing Objectives

The testing process aims to ensure that:

- All functional requirements operate correctly.
- APIs return expected results.
- AI services produce valid responses.
- Security mechanisms work properly.
- Performance targets are achieved.
- Users can complete shopping workflows successfully.

# 20.5 Unit Testing

Framework

```
JUnit 5
```

Scope

- Service Layer
- Utility Classes
- Business Logic
- Validation
- AI Gateway logic

Example

```java
@Test
void shouldGenerateTrustScore() {
    // Arrange
    // Act
    // Assert
}
```

Target

Minimum 80% service-layer coverage.

# 20.10 AI Testing

AI testing validates model outputs rather than exact wording.

Verify

- Sentiment classification
- Trust Score generation
- Review summary quality
- Recommendation relevance
- Fake review detection

Evaluation Criteria

- Correctness
- Consistency
- Explainability
- Response time

---

# 20.11 AI Model Validation

| AI Function | Validation |
|-------------|------------|
| Sentiment Analysis | Positive / Neutral / Negative classification |
| Fake Review Detection | Probability and reasoning |
| Trust Score | Score within expected range |
| Recommendation | Relevant to product context |
| Review Summary | Accurate and concise |

# 20.16 User Acceptance Testing (UAT)

Representative users execute business scenarios to confirm that the system satisfies project requirements.

Example Scenarios

1. Customer completes a purchase.
2. Customer submits a review.
3. AI generates a Trust Score.
4. Administrator moderates reviews.

Acceptance

All critical scenarios must complete successfully.

---

# 20.17 Regression Testing

Regression testing ensures that new features do not break existing functionality.

Executed after:

- Bug fixes
- Feature additions
- Database changes
- AI integration updates

# 20.22 Exit Criteria

Testing is considered complete when:

- No unresolved critical defects remain.
- All Must-priority functional requirements pass.
- Security testing is successful.
- Performance targets are achieved.
- UAT is approved.
- Deployment verification succeeds.

# 20.24 Chapter Summary

The testing strategy ensures that VeriCart AI is validated from multiple perspectives, including functionality, integration, security, performance, user experience, and Artificial Intelligence.

By applying layered testing practices and combining automated and manual validation, the project aims to deliver a stable, secure, and maintainable AI-powered e-commerce platform that satisfies both academic requirements and professional software engineering standards.
